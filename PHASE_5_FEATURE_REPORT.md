## 1. Executive Summary & Objective

Phase 5 transforms Phase 3 candidate pairs and Phase 4 baseline rankings into an 84-dimensional, highly discriminative, deterministic feature matrix for downstream machine learning (Phase 6).

$$\text{Candidate Pair } (S_1, \text{Cand}) \xrightarrow{\text{Phase 5}} \vec{x} \in \mathbb{R}^{84}$$

Phase 5 operates strictly within the candidate pool generated by Phase 3, avoiding any Cartesian product ($S_1 \times S_2$ or $S_1 \times S_3$). Every feature is deterministic, reproducible, and guarded against missing-value corruption.

### Key Results Highlights:
- **Total Candidate Pairs Extracted:** **170,153 candidate pairs**.
- **Class Distribution:** **8,508 Positive Pairs (5.00%)** vs. **161,645 Negative Pairs (95.00%)** ($1:19$ positive-to-negative ratio).
- **Throughput:** **10,954 pairs/second** (complete feature extraction in 15.53s).
- **Feature Quality Validation:**
  - **NaN values:** **0 across all 84 columns** (100% clean).
  - **Inf values:** **0 across all 84 columns**.
  - **Out-of-range values:** **0**.
  - **Missing value policy:** Missing fields are explicitly imputed with deterministic zeros or domain-appropriate neutral values; missingness itself is encoded in dedicated Group D features.
- **Top Statistical Discriminating Feature:** `address_token_overlap` achieved **Cohen's $d = 3.058$** (positive mean: **0.766** vs. negative mean: **0.123**).
- **Multi-Strategy Verification:** `blocking_multi_strategy` achieved **Cohen's $d = 2.917$** (**92.24%** of positive pairs were retrieved by $\ge 2$ blocking strategies, compared to only **9.79%** of negative pairs).
- **Data Leakage Guarantee:** The ground truth label `ground_truth_label` is strictly appended only as an isolated target column for supervised training artifacts and is explicitly excluded from the model feature column registry.

## 3. The 9 Pairwise Feature Groups

### Group A — Business Name Features (17 Features)
Captures lexical equality, typographical similarity, word reordering, acronyms, and length discrepancies:
- `name_exact_match`: Case-folded normalized equality.
- `name_core_exact_match`: Equality after stripping corporate legal suffixes (*LLC, Inc, Corp, Pvt Ltd*).
- `name_sorted_exact_match`: Word-order invariant token-sorted equality.
- `name_length_s1`, `name_length_cand`, `name_length_diff`, `name_length_ratio`: Character-level length dynamics.
- `name_token_count_s1`, `name_token_count_cand`, `name_token_count_diff`: Token cardinality dynamics.
- `name_token_jaccard`: $|A \cap B| / |A \cup B|$.
- `name_token_overlap`: $|A \cap B| / \min(|A|, |B|)$ (handles sub-brand / parent-brand inclusions).
- `name_char_3gram_jaccard`: Boundary-padded tri-gram overlap (tolerates OCR typos and minor transliterations).
- `name_levenshtein_sim`: $1.0 - \text{dist} / \max(L_1, L_2)$.
- `name_jaro_winkler`: Prefix-biased character transposition similarity.
- `name_prefix_similarity`, `name_suffix_similarity`: Ratios of common prefix and suffix lengths.

### Group B — Address Features (13 Features)
Compares physical location strings while remaining resilient to comma reorderings:
- `address_exact_match`, `address_sorted_exact_match`: Raw and component-sorted exact equality.
- `address_length_s1`, `address_length_cand`, `address_length_diff`, `address_length_ratio`: Address text lengths.
- `address_token_count_s1`, `address_token_count_cand`, `address_token_count_diff`: Address token cardinality.
- `address_token_jaccard`, `address_token_overlap`: Word-level spatial intersection.
- `address_char_3gram_jaccard`, `address_levenshtein_sim`: Character-level spatial similarity.

### Group C — Structured Field Features (10 Features)
Deterministic 4-way indicators for extracted physical components:
- `postal_exact_match`, `postal_both_present`, `postal_one_missing`, `postal_both_missing`: Extracted postal code comparison.
- `house_number_exact_match`, `house_number_both_present`, `house_number_one_missing`, `house_number_both_missing`: Street number comparison.
- `unit_exact_match`, `unit_both_present`: Apartment / Suite identifier comparison.

### Group D — Field Missingness Features (13 Features)
Directly models informative missingness patterns:
- `missing_s1_name`, `missing_cand_name`, `missing_both_name`, `missing_either_name`
- `missing_s1_address`, `missing_cand_address`, `missing_both_address`, `missing_either_address`
- `missing_s1_country`, `missing_cand_country`
- `missing_s1_postal`, `missing_cand_postal`
- `missing_field_count_total`: Integer count $\in [0, 8]$ of missing attributes across both records.

### Group E — Cross-Field Consistency (6 Features)
Deterministic interaction terms between strong independent matching dimensions:
- `cross_name_match_and_address_match`: Strict dual identity match.
- `cross_name_match_and_postal_match`: Name and postal alignment.
- `cross_name_sim_x_country_match`: Name token similarity gated by country match.
- `cross_name_sim_x_address_sim`: Multiplicative name $\times$ address similarity.
- `cross_address_sim_x_postal_match`: Address text similarity gated by postal match.
- `cross_country_and_postal_match`: Joint nation and postal code match.

### Group F — Generic Open-Set Country Features (4 Features)
> [!IMPORTANT]
> Zero country whitelisting: No hardcoded `US` or `India` values. Any unseen international country label (e.g. `France`, `Germany`, `Japan`) is cleanly handled:
- `country_exact_match`: Case-folded equality.
- `country_conflict`: Both declared but unequal (strong negative match indicator).
- `country_both_present`, `country_missing`: Country availability flags.

### Group G — Candidate Provenance Features (13 Features)
Captures how Phase 3 blocking discovered this candidate pair:
- `blocking_exact_name`, `blocking_exact_name_sorted`, `blocking_exact_country_name`
- `blocking_exact_country_postal_name`, `blocking_exact_country_postal_house`, `blocking_exact_country_house_token`
- `blocking_name_token`, `blocking_address_token`, `blocking_char_ngram`
- `blocking_tfidf_name`, `blocking_tfidf_addr`
- `blocking_strategy_count`: Total number of retrieving strategies $\in [1, 9]$.
- `blocking_multi_strategy`: Binary indicator for $\ge 2$ strategies.

### Group H — Source Indicators (3 Features)
- `source_cand_is_s2`: Candidate belongs to Target Source 2.
- `source_cand_is_s3`: Candidate belongs to Target Source 3.
- `source_s1_is_s1`: Anchor originates from Source 1.

### Group I — Phase 4 Baseline Signals (5 Features)
Incorporates Phase 4 deterministic baseline evidence:
- `baseline_score`: Composite baseline matching score $\in [0.0, 1.0]$.
- `baseline_rank`: Rank of candidate for this anchor ($1 = \text{best}$).
- `baseline_name_sim`, `baseline_address_sim`, `baseline_structured_sim`: Component scores.

## 6. Feature Redundancy & Collinearity Audit

A pairwise Pearson correlation check identified 17 collinear pairs at $|r| \ge 0.95$:
- `source_cand_is_s2` $\leftrightarrow$ `source_cand_is_s3` ($r = -1.000$): Exactly binary source partition.
- `missing_cand_address` $\leftrightarrow$ `missing_either_address` ($r = +1.000$): Anchor records have 0 missing addresses in training.
- `blocking_exact_name` $\leftrightarrow$ `blocking_exact_country_name` ($r = +1.000$): Exact name blocks are strictly partitioned within countries.
- `postal_exact_match` $\leftrightarrow$ `cross_country_and_postal_match` ($r = +1.000$): Country always matches in candidate blocks.

*Phase 6 Recommendation:* These features provide clear complementary context for tree models and can be safely ingested by LightGBM/CatBoost, which naturally handle collinear trees.

## 8. Handoff Contract for Phase 6 (ML Matching)

When Phase 6 begins, it must strictly adhere to the following contracts:
1. **Feature Input:** Read features from `output/phase5/train_feature_matrix.csv.gz`.
2. **Feature List:** Read feature names from `output/phase5/feature_metadata.json` (`features.keys()`).
3. **Target Label:** Use `ground_truth_label` exclusively as the supervision target $y \in \{0, 1\}$.
4. **Group-Aware Splitting:** Group K-Fold cross-validation must group by `source1_entity_id` so that an anchor's candidates are never split across train and validation folds.
5. **Class Imbalance:** Implement `scale_pos_weight = 19.0` or focal loss to reflect the $5.0\%$ positive base rate.
